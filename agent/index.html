marquee-mcp · Companion tool for Claude

Your coding agent
can drive Marquee.

marquee-mcp is a Model Context Protocol server for Marquee. Claude Code, Codex, or any MCP-speaking agent can build a listing end to end: capture real screens off the simulator, compose the set, research the market, audit the copy, and render the exact files App Store Connect takes.

Install

Double-click it.

For Claude Desktop, Marquee ships as an extension. Download it, double-click, done — no terminal, no runtime to install, nothing outside the extension's own folder.

Download marquee.mcpb

Universal macOS binary, 20 tools. Claude Desktop shows you every permission before it installs anything.

Or one command.

1For Claude Code, install the binary:

curl -fsSL https://vladamisici.github.io/marquee-site/agent/install.sh | sh
claude mcp add marquee -- ~/.marquee/bin/marquee-mcp

2Or Codex — add to ~/.codex/config.toml:

[mcp_servers.marquee] command = "~/.marquee/bin/marquee-mcp"

Prefer to see what you're running? Download the tarball (universal macOS binary) or read install.sh first — it only writes to ~/.marquee/bin. Sanity-check any time with marquee-mcp --selftest; it builds a whole project end to end and reports each stage.

What's free, what needs a key.

Creating projects, capturing screens, composing slides, previewing them and running the full ASO audit all work for free. The three paid outputs — exporting the screenshots, exporting the App Preview video, and preparing the App Store Connect upload — need a Marquee licence, the same unlock the app uses.

Paste your key into the extension's settings in Claude Desktop, or into ~/.marquee/license. Already bought Marquee on the Mac App Store? marquee-mcp runs outside the store and can't see that purchase — open Help ▸ Connect a Coding Agent in the app and request your key.

What it can do

The whole listing, hands-free.

Capture real screens. Boots a simulator, launches your build, sets the 9:41 status bar, captures — the screenshots App Review actually wants.

Compose and see its own work. Adds slides, sets design and copy, then renders previews back as images — the agent looks at the result instead of guessing.

Research and audit. The same market checks and listing audit as the Marquee app — verdicts with receipts, legibility measured off rendered pixels.

Direct the app preview. Per-scene duration, motion, transitions, Ken Burns drift and caption reveals — give the money shot six seconds and the filler two, from a prompt.

Render the deliverables. Spec-exact PNGs for every family and language, plus the 15–30s preview video with the audio track uploads require.

Preflight the whole thing. Slide counts, byte budgets, layout collisions, provenance — the same ship gate as the app.

The project it writes is a normal .marquee file. Open it in Marquee and take over any time.

By design

Two things it won't do.

It won't call generated artwork a real screenshot — every slide records where its image came from, and preflight blocks synthetic screens. And it won't publish: the agent prepares the upload bundle, but putting a listing in front of App Review stays your action, in Marquee or App Store Connect.

Why a separate download instead of inside the app? The agent captures real simulator screens and reads your project files wherever they live — two things a sandboxed App Store binary can't do. The Mac App Store app stays fully sandboxed; the agent is this small, open companion.
